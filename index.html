Fleet tooling I've built and run in production

Mostly from four years building software for autonomous yard trucks at Outrider. Each card is problem → what I built → result.

01

Fleet ops dashboard

problem
Dispatchers running autonomous trucks during customer rollouts needed one place to see, control and debug the fleet.
what I built
A full-stack dashboard for robot control, logs, telemetry and live video, with a Three.js 3D view of the yard and a React-based vehicle reprogramming view. Used by dispatchers during rollouts at production customer yards.
result
2× faster vehicle reprogramming.
02

Event-triggered data capture

problem
Recording all LiDAR all the time is expensive to store and move, and the moments engineers need get buried.
what I built
LiDAR recording triggered by events instead of recording everything, plus mission-bag upload to S3 so engineers could pull the data and debug field issues.
result
90% smaller ROS bags by recording only high-value topics. 50% less time to access field data after improving bag recording and cloud upload.
03

Field reliability tooling

problem
Config drift and hard-to-reach logs turn small field issues into long debugging sessions.
what I built
On-truck configuration verification before missions, live log streaming and a subscription-based logger. I also wrote the debugging docs other teams used.
result
Improved fleet reliability by detecting configuration mismatches before mission execution, reducing unnecessary ROS log traffic through selective subscriptions, and enabling faster remote debugging of autonomous trucks in production.
04

Robotic arm: real-time 3D visualization

earlier project
problem
Existing visualization tooling lacked the performance needed to efficiently monitor robotic-arm movements in real time.
what I built
A high-performance 3D web dashboard in React and Three.js that visualizes live robotic-arm motion from ROS topics.
result
~85% improvement in visualization performance over the legacy implementation.
